# SPC7110 and cartridge RTC

SPC7110 cartridges use a clocked decompression and arithmetic module, banked data ROM, battery RAM, and an optional RTC. No separate processor firmware is required.

## Clocks and registers

The processor runs at 21,477,272 Hz against the console's NTSC or PAL master clock. A decompression request waits 20 processor clocks before initializing its coding state. Multiplication waits 30 clocks and division waits 40. Results publish after the wait completes. Operations can queue while another wait is active; operands and controls remain live until the operation uses them.

Writing `$4806` clears decompression readiness and schedules a transfer. Reading `$480C` preserves the ready flag. Writing the table index at `$4804` latches the selected mode and compressed address; changing the table pointer alone does not reload them. The mode occupies two bits, and mode three does not start a transfer. `$480B` selects row seeking and row stride. Stream reads decrement the 16-bit byte counter even when output is not ready.

Multiplication and division publish their results in `$4828-$482D`. `$482F` reports busy and retains its operation bit across reads. Completing an earlier operation can clear busy while a queued operation is still waiting. Writing `$482E` changes signed arithmetic mode without clearing operands. Signed division handles the minimum dividend and negative-one divisor through a wider intermediate.

The data port prefetches when its pointer bank or control register is written. Reads of `$4810` return that prefetched byte, apply the selected signed or unsigned stride to the pointer or adjustment, and fetch the next byte. Adjustment modes can seek on the low-byte write, high-byte write, or `$481A` read. The latter port returns zero. Table and data pointers retain 23 address bits.

## Decompression

The three compressed modes produce one-, two-, and four-bit graphics. Each stream has independent arithmetic coding contexts, input state, pixel history, and color ordering. Decoded rows feed a 32-byte tile buffer in SNES plane order. A row can repeat or advance by the selected stride. Console reset clears controls and pending requests while retaining decoder and tile storage; another transfer reinitializes the coding state.

## CPU board map

| CPU window | Behavior |
| --- | --- |
| `$00-$3F/$80-$BF:$4800-$483F` | Processor registers |
| `$50:$0000-$FFFF` | Decompression stream port |
| `$58:$0000-$FFFF` | Reserved zero port |
| `$00-$3F/$80-$BF:$6000-$7FFF` | Battery RAM, gated by `$4830` bit seven |
| `$00-$3F/$80-$BF:$8000-$FFFF`, `$C0-$FF:$0000-$FFFF` | Program/data ROM controller |
| `$00-$3F/$80-$BF:$4840-$4842` | RTC ports, when present |

Program ROM occupies the first MiB. The remaining bytes are data ROM. A seven-MiB expansion image uses five MiB of data ROM and a separate final MiB at `$40-$4F:$0000-$FFFF`. Standard boards leave that expansion window unmapped.

Registers `$4830-$4833` select ROM banks, and `$4834` controls data-address visibility and the program mirror. Physical ROM sizes mirror independently of that address selection. Fresh battery RAM contains `$FF`. Loading a save replaces those bytes. Disabled battery RAM reads zero and ignores writes, while retaining its contents. CPU bank mirrors share the same save allocation.

## RTC and saves

The optional clock runs at 2,097,152 ticks per second. Its serial ports select a mode, seek to a register, then read or write calendar nibbles. Accepted mode, address, and data transfers wait eight RTC ticks before readiness returns. Reading status preserves readiness; reading calendar data starts another wait.

The clock models 12- and 24-hour time, calendar enable, leap years, hold, pause, stop, second rounding, interrupt flags and masks, and invalid BCD carry behavior. A held second is applied once when hold is released. Console reset clears the port interface and oscillator counters while retaining calendar and control storage.

A new clock has cleared calendar and control storage with its battery-failure flag set. It advances with emulated time while running. Loading a save applies elapsed host time. The existing 24-byte `.rtc` format remains supported: sixteen nibble-valued registers followed by an eight-byte little-endian Unix timestamp. Wrong sizes and values outside a nibble are rejected.

## Validation and limits

Generated tests cover delayed readiness, persistent status, live arithmetic inputs and queued operations, signed arithmetic edges, data prefetch and seeks, recorded compressed streams, SRAM gating and mirrors, expansion ROM, stream DMA, RTC handshakes, calendar transitions, and save round trips. Local audits compare full coding state, CPU timelines, clock balances, tile buffers, and final saves. RTC checks include invalid BCD values and port handshakes in both console regions.

These checks cover the exercised behavior. Complete game compatibility and measured physical-chip timings remain unverified.
