# ST018 firmware execution

ST018 cartridges can run supplied ARM firmware alongside the console CPU. The existing startup packet adapter remains available when firmware is absent; it does not execute the game's internal program.

## Firmware and clocks

`st018.rom` contains 131,072 program bytes followed by 32,768 data bytes, for 163,840 bytes total. Program words use little-endian byte order. The firmware catalog accepts this file through the same adjacent `firmware` folder or explicit directory used by the other cartridge processors. An appended firmware image takes precedence over the catalog. Firmware assets are not included.

The processor runs at 21.44 MHz. Its clock balance uses the console's NTSC or PAL master frequency. Execution can suspend at each processor memory or idle cycle, so a CPU mailbox access can occur between an instruction's bus operations. Splitting a clock interval preserves the processor state and results.

Bridge reads and writes first synchronize firmware execution to the current CPU clock. Between accesses, the processor batches independent work with at most 4,096 master clocks of deferred execution. Its work RAM is private and its timer does not raise an interrupt, so no CPU-visible event is skipped.

Reset holds the processor until released, then waits 65,536 processor clocks before asserting ready. A rising reset bit restarts registers, prefetch, and bridge controls. Work RAM survives a bridge reset. Releasing an already released reset bit leaves execution running.

## Processor and memory

The ARM engine includes conditions, barrel shifts, arithmetic and flags, branches, multiplication, status transfers, banked registers, exception entry, single and multiple memory transfers, and instruction prefetch. Each instruction begins in ARM mode. Prefetched instructions remain retained until consumed or a branch refills the pipeline.

| ARM address region | Behavior |
| --- | --- |
| `$00000000-$1FFFFFFF` | Program ROM, mirrored every 128 KiB |
| `$20000000-$3FFFFFFF`, `$80000000-$9FFFFFFF`, `$C0000000-$DFFFFFFF` | Current prefetch word |
| `$40000000-$5FFFFFFF` | Bridge registers, mirrored every 64 bytes |
| `$60000000-$7FFFFFFF` | Constant `$40404001` |
| `$A0000000-$BFFFFFFF` | Data ROM, mirrored every 32 KiB |
| `$E0000000-$FFFFFFFF` | Work RAM, mirrored every 16 KiB |

The board's memory interface supports byte and word accesses. Halfword ROM/RAM reads return zero and halfword RAM writes have no effect. Loads retain their width, sign extension, rotation, and idle-cycle behavior. Firmware ROM remains read-only.

## CPU bridge and saves

The CPU bridge occupies `$00-$3F/$80-$BF:$3800-$38FF`. Registers repeat every eight bytes and ignore address bit zero. Reading `$3800` consumes the output mailbox, reading `$3802` acknowledges the signal flag, and `$3804` reports status. Writing `$3802` replaces the input mailbox; writing bit zero of `$3804` controls reset.

Status bits are output ready at bit 0, signal at bit 2, input ready at bit 3, and boot ready at bit 7. Firmware reads input at ARM `$40000010`, reads status at `$40000020`, writes output at `$40000000`, and raises signal by writing `$40000010`. Three timer-latch bytes at `$40000020/$24/$28` load the internal timer through `$4000002C`; the modeled timer does not assert an interrupt.

Battery RAM is separate from the processor's 16 KiB work RAM. Its size follows the cartridge header. The supplied cartridge declares 8 KiB, so its two 4 KiB halves remain independent. Save banks mirror across both halves of each bank.

## Validation and limits

`snes_arm6_tests` covers flags, carry use, banked exception entry, retained prefetch, branch refill, and conditional memory access. `snes_st018_tests` covers generated firmware through cartridge and system-bus interfaces, boot timing in both regions, reset, clock partitioning, firmware selection, mailbox mirrors, and battery RAM. A generated console program sends a mailbox byte, waits for the ARM reply, and uses it as a palette color.

A local instruction audit matched 917,504 cases across opcode patterns, all conditions, and all register-bank modes. It compared complete register banks, status, memory, and ordered bus/idle events. A separate board audit matched 1,024 timelines with 512 CPU accesses each, including reset holds, mailbox interleaving, timer state, NTSC/PAL clock balances, all eight ARM address regions, and complete work RAM.

Two 6,000-field Hayazashi Nidan Morita Shougi 2 replays used the supplied program and data firmware. One covered menu navigation and player controls; the other selected the computer to move first and reached its opening move. Together they matched 6,397,374 shared stereo samples and all video fields apart from two diagnosed zero-brightness capture artifacts per replay. Zero brightness remains black in the core.

These checks cover the exercised sequences. They do not establish complete game compatibility or measured physical chip timings.
